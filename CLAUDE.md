Tailored CV upload via JavaScript DataTransfer, effective 13 August 2026, applied from the next scheduled run onward. The default upload path per role becomes JavaScript DataTransfer injection, and per portal manual profile upload becomes the fallback.

JavaScript DataTransfer injection is the default. For each auto-apply attempt on any company portal, the pipeline reads the tailored CV_Rahul_Rawat.pdf and CoverLetter_Rahul_Rawat.pdf from drafts/[folder]/ into base64, passes the base64 string into javascript_tool, and in the page context builds a File object wrapped in a DataTransfer that is assigned to the file input's files property with a change event dispatched. This is a modern browser API that lets a script set an input file the same way a native file picker would, and is the reason ATS forms cannot always distinguish programmatic uploads from native ones.

Verification gate is mandatory. After the injection completes, the pipeline reads the file input's current state and confirms three things before proceeding past the attachments section. The input.files.length must be 1. The input.files[0].name must match the injected filename. The input.files[0].size must equal the source PDF byte size within a small tolerance. If any of these three checks fail, the injection is treated as rejected and the pipeline stops on that portal.

On any portal where the injection fails or the ATS silently swaps the file back to a profile default, the pipeline writes a "manual upload required" flag onto the Notion row for every subsequent role at that same portal domain, and future runs skip the injection attempt on that domain and route to Option 1 fallback: pick the tailored CV that Rah manually uploaded to his portal profile most recently, or the default profile CV if no tailored variant exists. The digest states plainly which portals were on JavaScript injection this run and which fell back to profile upload.

Three ATS fixes, all baked into build_html.py:

1. CURRICULUM VITAE strip retired. The tracked spaced caps tag at the top of every CV (both HTML plus PDF and docx variants) is dropped entirely. Naive PDF text extractors, which is exactly what Workday, SuccessFactors, Greenhouse and most global ATS parsers use, output each letter on its own line because the source string contains real space characters between letters for extra kerning. That produces 16 lines of alphabet noise before the parser even sees Rah's name. The strip carried zero information value and only existed for visual flourish, so it is removed rather than reworked. The name still opens the header as the first parsed line, followed by the tailored role tagline and contact info as before.

2. Single column entry layout with inline date and location. The 19 July 2026 two column entry layout is superseded. Every entry in Berufserfahrung/Professional Experience, Persönliche Projekte/Personal Projects, Ausbildung/Education, and Forschung und Abschlussarbeit/Research and Thesis now renders as a single column block instead of a two column band. Entry title, italic subtitle, date range, and location all live on visible lines directly above the bullets, with the date range and location joined into a plain prose line like "Data Scientist at eRay GmbH, Heidelberg, Oct 2025 to Mar 2026" or "Junior Associate Software Developer at SS Engineers and Contractors, India, Aug 2023 to Aug 2024". No table, no two column band, no right aligned date tab stop. This is because naive ATS extractors read the visible left column of the two column band top to bottom first, then the right column top to bottom, which pairs Rah's dates and locations with the wrong entries when the label to value pairing is column dependent. The single column layout removes that failure mode. The Persönliche Daten block also flattens from a two column key value table to a one line per field format written as "Adresse: C2 16, 68159 Mannheim, Deutschland" and so on. This costs a little visual density but survives every ATS parser tested. The 19 July 2026 CURRICULUM VITAE header rule and the 19 July 2026 rust secondary accent restore rule stay in force on colours and section rules, only the layout mechanics change.

3. Fähigkeiten and Skills section added. A new standalone section titled Skills on the English track or Fähigkeiten on the German track is inserted directly after Profil and before Berufserfahrung. It renders as one comma separated line of the top 20 to 25 keywords Rah has actually shipped, drawn from the union of every stack list in master-projects.md across the projects picked for that posting plus the eRay stack and the SS Engineers stack. Example on English track, "Python, SQL, PySpark, BigQuery, Databricks, Delta Lake, Power BI, Tableau, LangChain, LangGraph, CatBoost, LightGBM, XGBoost, Prophet, MICE, scikit-learn, dbt, Apache Airflow, GCP, AWS, Docker, Git, React, Playwright". This section exists purely for keyword coverage, since every serious ATS scoring model weights a dedicated Skills or Fähigkeiten block heavily. The rest of the CV already spreads these skills across the project descriptions and Technologies lines at the end of each entry, but a keyword parser can miss half of them without the standalone block.

Ordering after the fixes stays Persönliche Daten, Profil, Skills or Fähigkeiten, Berufserfahrung, Ausbildung, Persönliche Projekte, Forschung und Abschlussarbeit, Zertifikate, Auszeichnungen, Sprachen.
